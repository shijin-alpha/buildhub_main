🐛 Debug Payment Receipt Upload Issue

Analyzing why receipt upload works from "View Details" but not from "Pay Now" flow.

🔍 Issue Analysis

Problem: Receipt upload works from "View Details" but fails from "Pay Now" flow.

Two Different Paths:

Path 1 - View Details (Working):
HomeownerProgressReports → PaymentReceiptUpload
paymentId = selectedPaymentRequest?.id (stage_payment_requests.id)
Path 2 - Pay Now (Not Working):
HomeownerProgressReports → PaymentMethodSelector → PaymentReceiptUpload
paymentId = alternativePaymentId (alternative_payments.id)

❌ Root Cause Identified

The issue is that the PaymentReceiptUpload component and the backend API expect different types of payment IDs:

  • View Details path: Uses stage_payment_requests.id (original payment request)
  • Pay Now path: Uses alternative_payments.id (alternative payment record)

The backend API upload_payment_receipt.php likely expects the original payment request ID, not the alternative payment ID.

✅ Solution

We need to modify the PaymentMethodSelector to pass the original payment request ID instead of the alternative payment ID:

Current (Broken):
<PaymentReceiptUpload
  paymentId={alternativePaymentId} // ❌ Wrong ID
/>
Fixed:
<PaymentReceiptUpload
  paymentId={paymentRequest?.id} // ✅ Original payment request ID
/>

🔧 Additional Considerations

  • The alternativePaymentId is used for tracking the alternative payment method initiation
  • The receipt upload should still reference the original payment request
  • The backend API should handle both scenarios properly
